# Claude Code 执行提示词：导出“精彩信通”公众号全部推文为 HTML

你现在在本机仓库中工作，目标是只使用 `wechat-rss/` 这一套能力，把微信公众号“精彩信通”的所有已抓取推文导出为独立 HTML 文件，并保留正文内容。

## 任务目标

请在本地 `wechat-rss` 服务中找到公众号“精彩信通”，导出这个公众号当前在 `wechat-rss` 数据库里可访问到的全部推文。

导出要求：

1. 每篇推文导出为一个独立的 `.html` 文件。
2. HTML 内必须包含：
   - 标题
   - 公众号名称
   - 发布时间
   - 原文链接
   - 正文内容
   - 正文中的图片链接尽量保留
3. 文件命名格式必须为：

   `YYYY年MM月DD日｜标题.html`

4. 如果同一天存在同名文章，允许自动追加序号避免覆盖，例如：

   `2026年05月15日｜某标题（2）.html`

5. 导出目录单独新建，不要和其他导出内容混在一起。

## 范围约束

## 执行要求

请按下面顺序完成：

### 1. 先确认服务可用

先检查本地 `wechat-rss` 服务是否在线。

如果服务在线，再继续。

### 2. 搜索公众号并确认目标

通过 `wechat-rss` 的搜索接口查找“精彩信通”，确认命中的公众号确实是：

- 名称：`精彩信通`
- 简介接近：`宁波港信息通信有限公司官方公众号`

记录它的 `mp_id`。

### 3. 获取该公众号全部文章列表

通过 `wechat-rss` 的文章接口拉取这个公众号的文章列表。

注意：

- 文章列表可能需要分页
- 允许长时间等待
- 不要因为单次请求稍慢就提前中断
- 如果接口有 `limit` / `offset` 之类参数，请持续翻页直到该公众号当前可取到的文章全部拿完

### 4. 逐篇获取文章详情

对列表中的每一篇文章，再调用详情接口获取正文。

优先使用正文相关字段，例如：

- `content_html`
- 若没有，再看是否存在 `content`
- 再不行才回退到摘要或占位说明

目标是“尽可能保留正文内容”，尤其是：

- 段落
- 图片
- 列表
- 表格
- 正文中的换行结构

### 5. 生成独立 HTML 文件

每篇文章生成一个独立 HTML 文件。

要求：

- 使用 UTF-8
- 可以套一层简洁的阅读模板
- 但不要把正文结构打散
- 尽量保留原始正文 HTML
- 可以裁掉明显不属于正文的尾部噪音区，例如：
  - 往期推荐
  - 公众号尾部交互提示
  - “预览时标签不可点”
  - 点赞、在看、分享按钮区

### 6. 命名与目录

请创建一个独立目录，例如：

`/Users/wangrundong/work/infomation-center/wechat-rss/exports/精彩信通_html`

命名规则：

`YYYY年MM月DD日｜标题.html`

要求：

- 清理文件名中的非法字符，如 `/ \\ : * ? " < > |`
- 尽量保持原标题不变
- 不要改成拼音
- 不要改成无意义的 article_001 这种名字

### 7. 允许长时间等待

这是重点：

- 如果分页或单篇详情请求慢，请允许长时间等待
- 不要因为几十秒甚至更久的等待就放弃
- 可以串行跑，不要求高并发
- 更重要的是稳定完成，而不是快

如果某一篇失败：

- 做有限重试
- 记录失败项
- 继续处理其他文章

### 8. 最终验证

完成后请验证：

1. 导出目录是否存在
2. 文件总数是否等于该公众号当前可导出的文章数
3. 随机抽查几篇 HTML：
   - 标题正确
   - 时间正确
   - 正文存在
   - 图片链接存在
4. 文件名是否符合 `YYYY年MM月DD日｜标题.html`
